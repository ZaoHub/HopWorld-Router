# 运行环境适配路线图

本文记录 HopWorld Router 的后续适配计划，方便按阶段实施和验收。除已有 README 明确说明的功能外，以下均为待完成事项；有安装步骤或镜像不等于已经通过对应设备的实测。

## 先确定每个平台的支持范围

每个环境分别记录以下功能，不因某一项通过就宣布全部支持：

- **订阅管理**：登录管理页、添加和更新订阅、保存设置、生成订阅。
- **节点测试**：Xray 与 curl 可用，测试结果和失败原因正确显示。
- **本地网络节点**：Xray 启动与恢复、外部客户端连接、订阅更新。
- **系统 VPN（IKEv2）**：系统依赖、权限、设备接入和联网；不能复用 Linux 方案时单独标明。
- **证书与动态 DNS**：按该环境实际配置验证签发、续期和更新；未适配时明确标注。

每次发布安装教程时，记录设备、系统版本、CPU 架构、安装方式、验证日期和各项功能结果。还要检查重启恢复、升级与回滚、数据备份，以及管理界面和订阅地址的访问控制。没有实际验证的项目标为“未验证”，失败项记录限制和复现条件。

## 阶段一：验证 Linux 基础

目标：先把现有安装教程变成经过实际验证的基础，再向其他环境扩展。

1. 在 Debian / Ubuntu 和 RHEL / Rocky / AlmaLinux 选定具体版本，分别从全新系统按 README 安装；记录 Python、Xray、systemd 与架构版本。
2. 在 Linux Docker 上构建镜像并检查 Xray、curl、数据目录和宿主机网络；分别验证 x86_64 与 ARM64 可用的设备或虚拟机。
3. 按上面的功能范围逐项验证；检查服务和容器重启后数据、配置和已启用节点的恢复。
4. 根据实测结果修正安装步骤，列出不支持或需要额外配置的功能。

**完成条件**：每种已声明支持的组合都有实测记录、可复现的安装与恢复步骤；未测组合仍明确标为未验证。

## 阶段二：NAS、ARM 小主机与 Linux 虚拟机

目标：优先复用 Linux 与容器方案，逐设备完成适配。

首个计划实测的 NAS 型号为绿联 DXP4800 Plus；UGOS Pro 版本和具体验证结果待记录。飞牛需选择具体硬件和系统版本后分别验证。

1. 分别选择群晖、威联通、极空间、绿联 NAS（UGOS Pro）和飞牛私有云（fnOS）中具备容器能力的具体设备或安装环境，记录型号、系统版本和架构；确认容器网络、持久化目录和备份方式。飞牛自装环境还需记录硬件配置。
2. 为实际测过的平台编写安装、更新和卸载教程。确认管理界面访问方式以及本地节点端口如何对外提供；IKEv2 和证书功能分别核实。
3. 在树莓派或其他 ARM 小主机、Linux 虚拟机中验证架构匹配、开机启动、网络和持久化；记录资源限制及依赖版本。
4. 将结果分别填入平台支持记录，不把一个 NAS 型号的结果推广到所有型号。

**完成条件**：每个列为支持的设备或系统组合都有对应教程，并完成阶段一适用的功能和恢复验证。

## 阶段三：Windows WSL 2 与 Docker Desktop

目标：在 Windows 和 macOS 桌面环境中，以 Linux 子系统或容器运行服务。

已提供 [Windows WSL 2 试用指南](Windows-WSL2试用指南.md)和 [Docker Desktop 试用指南](Docker-Desktop试用指南.md)，均尚未实测；WSL 目前采用手动启动，后台服务和其他功能仍需按以下步骤完善。

1. 在 Windows WSL 2 中选择具体发行版，验证依赖、systemd 配置、数据持久化及服务启动方式。
2. 分别验证 Windows 与 macOS 上的 Docker Desktop：确认版本和网络设置、管理页访问、本地节点入站与数据目录；不要假设网络行为与 Linux 主机完全相同。
3. 检查电脑重启、休眠唤醒和系统更新后的恢复。明确说明电脑关机或休眠期间的服务可用性。
4. 按环境编写安装教程；订阅管理、节点测试、本地节点、IKEv2 和证书分别标注验证结果。

**完成条件**：选定的系统版本与运行方式有安装和恢复记录，网络访问及功能限制已在教程中写清楚。

## 阶段四：macOS 和 Windows 原生后台服务

目标：不依赖用户保持终端窗口开启，并提供各系统合适的安装和管理方式。

已准备 [macOS 用户后台服务试用指南](macOS后台服务试用指南.md)和配置生成脚本，以及 [Windows 原生订阅管理试用指南](Windows原生试用指南.md)；均尚未在目标系统完成实际验证。Windows 原生的本地节点已暂时禁用，进程管理仍需适配。

1. macOS：设计并验证后台服务、启动与停止、开机或登录后启动、日志、升级和卸载。
2. Windows：适配进程启动与停止、文件权限和路径，设计 Windows 服务、Xray 管理、日志与升级卸载。
3. IKEv2、证书和动态 DNS 按平台分别评估与实现；未适配的功能不要标为可用。
4. 在对应系统上验证安装、重启、异常恢复、数据保留和卸载。

**完成条件**：每个原生平台有可重复的安装和卸载步骤、后台运行及恢复验证，并逐项说明功能范围。

## 阶段五：OpenWrt

目标：针对具体路由器和 OpenWrt 版本提供可维护的安装方式。

已准备实验性的 [OpenWrt 试用指南](OpenWrt试用指南.md)和 procd 服务模板，仅用于订阅管理；尚未制成安装包，也没有设备验证记录。

1. 选择设备型号、CPU 架构、OpenWrt 版本和存储条件，确认 Python、依赖及 Xray 的可用性和资源占用。
2. 制作适配 OpenWrt 的安装包和 procd 服务配置，处理持久化、日志、升级与卸载。
3. 分别验证订阅管理、节点测试和本地节点；评估 IKEv2、证书与动态 DNS 的依赖和权限。
4. 在真实设备上验证重启、网络变化和异常恢复。透明网关、DNS 接管与防火墙联动须单独设计和验收，不默认包含在本阶段。

**完成条件**：列出的设备组合有实机验证记录、安装包及教程，资源需求和未支持功能清楚可见。

## 支持记录模板

每完成一个组合，将以下信息追加到项目文档或发布说明：

| 项目 | 记录内容 |
| --- | --- |
| 设备 / 系统 / 架构 | 具体型号、系统版本、CPU 架构 |
| 安装方式 / 验证日期 | 原生、容器等；实际验证日期 |
| 订阅管理 / 节点测试 / 本地节点 | 分别填写通过、失败或未验证，并记录条件 |
| IKEv2 / 证书 / 动态 DNS | 分别填写通过、失败、未适配或未验证 |
| 恢复与数据 | 重启、升级、备份和恢复的验证结果 |
| 限制与教程 | 已知问题、环境条件和对应安装文档链接 |
