# HopWorld Router V1 开发与验收

V0 使用本地 Git 标签 `v0`。V1 开发位于 `codex/v1`，参考「首次落地版本」交付包的八张界面图及 P0 验收矩阵。当前开发版保留 Python 和 SQLite，以便沿用 V0 的订阅、节点和证书数据。交付包中的 Go 和 Vue 是推荐技术栈，当前开发版继续基于现有实现。

| 页面 | 本阶段可用 |
| --- | --- |
| 首页 | 节点、运行内核、流量、公网与证书概览 |
| 内核管理 | 六种内核使用各自的配置、进程、监听端口、日志和自动恢复设置 |
| 节点管理 | 导入、搜索、测试、上游显示名称和订阅启停。本地发布节点可复制 URI、显示二维码或下载客户端配置。独立发布节点用同一内核的客户端测试网页连通性 |
| 订阅管理 | HTTPS 订阅、启停、编辑、按源自动更新、ETag / Last-Modified 条件请求、内网访问防护、统一导出 |
| 域名与证书 | 已绑定的公网域名、DDNS、ACME 签发和续签、手动导入 PEM 证书 |
| 公网接入 | 本机入口、自有 VPS 的 FRP TCP/UDP 中转、注册状态和日志，保留 IKEv2 配置 |
| 流量监控 | 独立发布实例实时计数、按协议与端点统计、旧版 Xray 历史分开查询 |
| 系统设置 | 主机信息、程序更新设置和数据库快照下载，部署端可加密备份并恢复 Router 数据 |

新安装默认绑定指定上游。绑定缺失、停用、被移除或不兼容时阻断业务，HTTP 上游仅供 TCP 转发。已有配置保留原出口设置。网页显示进程和配置状态，实际 TCP、UDP、QUIC 可达性需单独验收。

本地启动使用独立数据目录，以免影响 V0 的数据：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
HOPWORLD_HOST=127.0.0.1 HOPWORLD_PORT=18080 HOPWORLD_DATA=./data/v1-dev \
.venv/bin/python -m router.server
```

访问 `http://127.0.0.1:18080`，新安装使用 `admin / admin` 并在首次打开时设置新密码。新密码至少 6 个字符，字符类型不限。测试运行 `.venv/bin/python -m unittest discover -s tests`。CI 配置包含 Python 回归和 JavaScript 语法检查。

### 内核独立发布

公网部署时，在 RAKsmart 等云安全组和主机防火墙按实际监听放行入站。HTTPS 订阅默认使用 **TCP 9443**，修改端口后同步调整两处规则。节点发布按「公网接入」列表中的协议和端口放行。Reality 使用 TCP，Hysteria 2 和 TUIC v5 使用 UDP，开启 TCP 和 UDP 的 Shadowsocks 需要两条规则。仅绑定回环地址的节点走本机或已配置的中转。

启用 `HOPWORLD_MANAGEMENT_LOCAL_ONLY=1` 后，通过本机或 SSH 端口转发访问管理台。已分发的旧版订阅链接可继续使用，向新客户端分发 HTTPS 订阅地址。

需要公网管理台时，可在 Nginx 的 HTTPS 域名下反代到回环地址，并设置 `HOPWORLD_MANAGEMENT_HTTPS_HOST` 为该域名。反代须覆盖 `Host` 和 `X-Forwarded-Proto`，将登录 POST 按客户端 IP 限速。浏览器通过 TCP 443 登录，原 HTTP 首页仅跳转到 HTTPS。

在「内核管理」安装所需内核，点击「启动」选择订阅地址类型、地址族、监听端口及出口。监听默认限于本机，适合 FRP。直接接入需勾选「允许其他设备连接」，并按所选地址族放行实际入站。QUIC 入站使用与订阅域名匹配的证书，可先在「域名与证书」配置。

- **域名**支持 IPv4、IPv6 和双栈。在「域名与证书 → 绑定域名」先选客户端公网入口，再按提示配置 A、AAAA 或两类记录，并验证登记。FRP 中转时记录指向已登记的 VPS。有公网入站能力时可选本机直入，并从异地验证实际连通性。独立节点配置与证书申请使用已绑定域名列表。
- **动态公网 IP + 域名**可启用 DDNS。复用现有 DNS 更新环境变量，AAAA 和双栈使用支持 IPv6 的 DNS Webhook。探测或更新失败时保留上次地址并显示状态。调整地址族时，旧记录由 DNS 管理员清理。FRP 域名应始终指向 VPS。
- **自动公网 IP**按所选的 IPv4 或 IPv6 探测并更新订阅，默认每 30 秒检测一次，可通过 `HOPWORLD_PUBLIC_HOST_POLL` 调整。检测绕过 HTTP 代理配置，仍使用系统路由。客户端地址变化后需刷新订阅。QUIC 节点可以通过 IP 连接，同时使用「域名与证书」配置的证书域名校验 TLS。

证书进入续签窗口后，Router 会检查 Certbot 是否实际产生新证书，并校验证书和私钥成对后同步。Certbot 文件由 root 管理时，使用已有的 `deploy/hopworld-install-certbot-renew-hook.sh` 部署同步钩子。续签异常会记入证书日志。在原证书仍有效时，已发布的 QUIC 节点可继续使用它。

已有证书时，从本机管理地址或后台 HTTPS 打开「域名与证书 → 导入证书」。选择已绑定域名，上传证书链和未加密的 PEM 私钥。校验通过后会切换当前生效的证书，并重新加载使用该域名的 QUIC 服务。手动证书到期前需要重新导入。客户端仍按自己的受信任 CA 验证证书链。

本机可用 `HOPWORLD_HYSTERIA` 和 `HOPWORLD_SINGBOX` 指定内核路径后运行 `.venv/bin/python -m tests.e2e_certificate_renewal`，复现续签失败保留旧证书、续签成功后重新握手，以及导入证书后通过节点链接建立 TCP/UDP 会话。测试使用临时证书和模拟 Certbot。

订阅拉取通过系统路由直接连接经校验的公网 IP，保留对原订阅域名的 HTTPS 校验。含有内网地址的解析结果会被拒绝。服务端返回 304 时，保留已有节点、启停状态和上次内容更新时间，更新下一次检查时间。上游仅修改链接名称或 VMess 的 `ps` 时，Router 会合并重复节点并保留停用状态、管理台显示名称和固定出口绑定。连接地址、凭据或 TLS 参数变化后，Router 将其视为新节点，原固定出口按不可用处理。升级时会迁移数据库里仍有原链接的旧节点绑定。可在「节点管理 → 编辑节点」设置控制台显示名称，留空即可跟随原始名称。

| 内核 | 独立入站 | 当前独立出口 |
| --- | --- | --- |
| Xray-core | VLESS Reality | 本机直连或兼容的固定上游 |
| sing-box | Hysteria 2 和 TUIC v5 | 本机直连或固定 SOCKS5 上游 |
| mihomo | Shadowsocks | 本机直连或固定 SOCKS5 上游 |
| Hysteria 2 | 原生 Hysteria 2 | 本机直连或固定 SOCKS5 上游 |
| shadowsocks-rust | Shadowsocks | 本机直连 |
| TUIC Server | 原生 TUIC v5 | 本机直连 |

每种内核各自保存认证凭据。启动成功后加入统一订阅，停止会移除对应条目。固定上游被停用或移除时会停止对应发布服务，恢复可用后按已保存的配置恢复。直连只能显式选择。旧版发布可从「公网接入 → 端口映射管理 → 独立配置」切换，表单会预填原地址和端口。由旧 sing-box 提供的 Hysteria 2 和 TUIC 一起切换，继续运行的旧版 QUIC 服务须先切换或停止，再切换其依赖的旧 Xray。切换会短暂中断连接。连接地址或端口改变后，请更新客户端订阅。

流量监控使用 Xray、Hysteria 2、mihomo 和带 Clash API 的 sing-box 原生计数器。一个实例发布多种协议时，只统计该实例合计。Shadowsocks-rust 和 TUIC Server 当前显示为无可用分向计数。现有旧版 Xray 历史可在流量页切换查询。内核配置导出可通过 SSH 隧道或 HTTPS 管理入口下载，服务端配置备份保存在数据目录的 `core-config-backups`。

端口行的「切换内核」可在兼容的发布内核之间迁移 Hysteria 2、TUIC v5 和 Shadowsocks。迁移沿用原端口、认证凭据和订阅链接，中转节点的 VPS 映射随节点迁移。目标内核已有其他端口的发布时，Router 为迁入端口使用独立进程，保留原发布。若独立 sing-box 的另一协议具有相同的地址和出口设置，可以共用原进程。额外端口可在内核设置中单独配置和停止。使用原生 Hysteria 2 的公网 IP 证书模式时，先改用域名证书再迁移。

独立 TUIC Server 使用 [Siglud/tuic v1.0.0](https://github.com/Siglud/tuic/releases/tag/v1.0.0)，GPL-3.0。安装器锁定对应平台的发布资产和 SHA256。Linux 上的 TUIC Server 和 Shadowsocks-rust 使用上游提供的 musl 包，以兼容旧版 GLIBC。TUIC 已通过 macOS ARM64 和 Linux x86_64（GLIBC 2.17）的本机 TCP/UDP 回环验证，长时间部署待验收。

安装器在替换文件前校验发布包哈希，并在目标主机试运行即将安装的服务端和配套客户端。新增内核时，应核实操作系统、架构和运行库要求，并在最低支持的系统版本上验证安装与实际启动。

「节点管理」对 Hysteria 2 和 TUIC 发起真实 HTTP 请求测试。导入的 Hysteria 2 节点优先使用已安装的原生 Hysteria 2 客户端，缺少原生客户端时使用 sing-box。导入的 TUIC 节点使用 sing-box。测试校验 TLS 证书，结果用于判断目标站点能否响应。UDP 业务需另外测试。

节点管理默认使用轻量转发测试。VLESS（含 TCP REALITY / Vision）、Trojan 的 TCP 和 WebSocket 连接，以及 Hysteria 2、HTTP(S) 和 SOCKS5，可由 `hopworld-probe` 完成节点认证和实际网页请求。程序只发送一次请求，保留 TLS 校验，不监听本地端口。其他传输方式和完整测试使用已安装的对应内核。缺少客户端时，页面会提示下载对应内核。

在构建机使用 Go 1.26 或更新版本，从 `probe-client` 目录构建 `CGO_ENABLED=0 go build -trimpath -ldflags '-s -w' -o hopworld-probe .`，将目标平台的二进制放到 Router 数据目录的 `bin/`。管理服务运行时无需 Go 工具链。

在「节点管理」选中本地发布节点后，可复制 URI，或打开「导出节点」下载客户端配置、显示二维码。二维码由浏览器根据同一导出 URI 生成，包含发布地址、VPS 映射后的端口和连接凭据。当前配置导出范围为 Mihomo YAML 的 Shadowsocks 和 Hysteria 2、sing-box JSON 的 Shadowsocks、Hysteria 2 和 TUIC，以及 Xray JSON 的 VLESS。配置默认只在客户端本机监听，端口分别为 7890、2080 和 10808。请按凭据保管配置文件和二维码。

独立发布节点的单测和批测使用发布地址及映射端口。Shadowsocks-rust 和 TUIC 使用同项目的 `sslocal` 和 `tuic-client`。从「内核管理」安装时会一并下载。已有服务端可通过「检查更新」补装缺失的客户端。手动安装可将客户端放在服务端同目录或系统 PATH，也可分别设置 `HOPWORLD_SSLOCAL` 和 `HOPWORLD_TUIC_CLIENT`。

### 数据库快照与停服恢复

在「系统设置 → 系统维护」的「备份与恢复」中可下载 SQLite 快照。快照含管理员验证器、订阅、节点、配置引用和流量历史，宜放在仅管理员可读的加密存储。迁移证书和私钥时使用下方的加密备份。回退到旧程序版本时应使用升级前的备份。

从项目目录用服务运行账号执行校验。将示例路径替换为自己下载的可信快照和实际 `HOPWORLD_DATA` 目录。第一条命令只检查快照。

```sh
.venv/bin/python -m router.database_backup /path/to/backup.db --data-dir /var/lib/hopworld-router
```

在 Linux、macOS 或 WSL 中停止使用该数据目录的 Router 服务，再执行恢复。目标库存在时，会在数据目录生成 `router-before-restore-*.db` 以便回退。完成后启动服务，核对管理员登录、入口端口、订阅和内核状态。

```sh
.venv/bin/python -m router.database_backup /path/to/backup.db --data-dir /var/lib/hopworld-router --apply
```

### 加密备份与数据目录迁移

在 Linux、macOS 或 WSL 中安装 `age`，把该工具加入 `PATH`。保管私钥的一端生成恢复密钥，备份主机只需取得 `age1…` 公开接收者。私钥与备份文件分别保管。 [age 官方发行版](https://github.com/FiloSottile/age/releases)

```sh
umask 077
age-keygen -o /path/to/router-recovery.key
age-keygen -y /path/to/router-recovery.key
```

停止 Router 后，以服务运行账号在项目目录执行。将 `--data-dir` 改为实际的 `HOPWORLD_DATA`，将接收者换成上一条命令输出的公钥。备份包含 Router 数据库、缓存的 ACME 证书、手动导入证书及对应私钥。输出目录应允许服务账号写入并支持硬链接，以便完整生成后再发布文件。

```sh
.venv/bin/python -m router.backup_archive create /path/to/router.age \
  --data-dir /var/lib/hopworld-router --recipient '<替换为 age1… 公开接收者>'
```

使用自己生成的备份文件和对应私钥。恢复目标必须是一个尚未创建的目录，父目录应已存在。工具验证加密负载、数据库完整性和证书密钥对，并将证书引用更新到新目录。确认恢复结果后，将服务的 `HOPWORLD_DATA` 指到新目录，并准备该主机所需的内核二进制。若使用系统 Certbot 续签钩子，也要更新它的证书缓存位置。

```sh
.venv/bin/python -m router.backup_archive restore /path/to/router.age \
  --data-dir /var/lib/hopworld-router-restored --identity /path/to/router-recovery.key
```

迁移自动续签或公网中转时，还需在对应主机配置 Certbot 账户及续签任务、环境文件中的 DNS 授权、VPS 端的 `frps` 与防火墙。Router 的入站凭据、VPS 连接设置和订阅个性化设定随数据库恢复。内核运行配置由 Router 启动时重建。

### Linux 原生测试包

在具备 Python 3.10+ 和 `dpkg-deb` 的构建机，从项目目录生成本地 `.deb` 和 SHA-256 文件。测试包只包含管理服务。代理内核按目标架构在「内核管理」安装。版本号 `1.0.0~dev1` 用于本地测试，正式发布通过验收后再签名分发。

```sh
python3 deploy/build-deb.py --version 1.0.0~dev1 --output build/linux-deb
```

将 `.deb` 和对应 `.sha256` 放在测试机同一目录。目标使用带 systemd 的 Ubuntu 22.04+ 或 Debian 12+。APT 从系统源安装 Python 和所需运行时依赖。现有 `/opt/hopworld-router` 或本地同名服务应先迁移，否则软件包会拒绝安装。

如需严格 LAN 网关，安装普通管理服务之外，还须在目标主机运行独立部署预检。它会分别核对系统工具和 VPS 实际提供的内核能力。配置拓扑和接入 LAN 前先确认结果为 `READY_FOR_TOPOLOGY`。[网络安全部署预检](V1网络安全与验收.md#新服务器部署预检)

```sh
sha256sum -c 'hopworld-router_1.0.0~dev1_all.deb.sha256'
sudo apt install './hopworld-router_1.0.0~dev1_all.deb'
systemctl is-enabled hopworld-router.service
systemctl is-active hopworld-router.service
```

安装时终端会打印管理地址、SSH 转发、服务状态、日志和恢复命令。网页打不开时，可以再次运行 `sudo hopworld-router-check` 查看这些命令和本机就绪状态。默认管理地址为 `http://127.0.0.1:8080`。新数据目录首次登录使用 `admin / admin` 并设置新密码。未认证的 `/api/status` 请求会返回 401。通过 `/etc/hopworld-router.env` 可覆盖运行配置，文件应仅由 root 读取。数据默认放在 `/var/lib/hopworld-router`，安装和卸载均由 APT 管理。

```sh
sudo journalctl -u hopworld-router.service -n 80 --no-pager
sudo systemctl restart hopworld-router.service
sudo apt remove hopworld-router
```

卸载后可使用原软件包重新安装，数据库、已缓存证书、内核二进制和管理员自行配置的环境文件可继续使用。软件包安装中的备份命令应从 `/usr/lib/hopworld-router` 执行，把上节的 `.venv/bin/python` 换成 `/usr/bin/python3`。用 `hopworld-router` 服务账号创建备份和恢复，选择该账号可写的输出目录及恢复目标父目录。

需要完整卸载并永久删除应用数据时，在交互式终端运行 `sudo hopworld-router-uninstall`。它会离线验证当前 Router 管理员密码，并要求输入 `UNINSTALL`。直接使用 `apt remove` 或 `apt purge` 时会保留应用数据库、证书缓存和管理员维护的环境文件。

升级前先停服创建加密备份，并保留当前版本 `.deb`。需要回退时，先停服，把旧数据恢复到新目录，将 `/etc/hopworld-router.env` 的 `HOPWORLD_DATA` 指向该目录，再校验旧包并用 `sudo apt install --allow-downgrades ./旧版文件.deb` 安装。恢复目录所需的内核二进制可从已保留的数据目录迁移或重新安装。

已在全新 Ubuntu 24.04.5 ARM64 虚拟机验证 APT 安装、首次登录、回环监听、安装 Xray 后通过导出的 Reality 配置代理 HTTPS 请求、软件包升级与手动降级、保留数据卸载及重装。虚拟机重启后，systemd 自动启动服务并恢复账号、订阅和 Xray 节点。开发包的升级和降级测试使用相同数据库结构。

### 本机真实进程测试

设置 `HOPWORLD_XRAY`、`HOPWORLD_SINGBOX`、`HOPWORLD_MIHOMO`、`HOPWORLD_HYSTERIA`、`HOPWORLD_SSSERVER` 和 `HOPWORLD_TUIC_SERVER` 后运行 `.venv/bin/python -m tests.e2e_independent_cores`，可验证六个内核各自单独启动、通过认证后转发 TCP/UDP，以及停止 Xray 时其余内核继续运行。

```sh
HOPWORLD_TEST_XRAY=/绝对路径/xray \
HOPWORLD_TEST_SINGBOX=/绝对路径/sing-box \
HOPWORLD_TEST_HYSTERIA=/绝对路径/hysteria \
.venv/bin/python -m tests.e2e_fixed_upstream
```

只设置 Xray 时运行 Reality 测试。加入 sing-box 后再测 Hysteria 2 和 TUIC，加入 Hysteria 2 后再测原生服务。测试在回环地址上运行真实进程和合成业务，覆盖 TCP/UDP 往返、固定上游断开时阻断、TCP/UDP 端口冲突，以及 Xray 修改端口失败时恢复上一份运行配置。

### 家庭 CGNAT 经自有 VPS 发布

家庭 Router 运行 `frpc`，VPS 运行 `frps`。两端用 [FRP v0.72.0 发布资产及 SHA-256](https://github.com/fatedier/frp/releases/tag/v0.72.0)。将 `frpc` 放入 Router 服务的 `PATH`，也可为服务设置 `HOPWORLD_FRPC=/绝对路径/frpc`。Docker 部署需将匹配容器架构的二进制放入容器。

1. 将统一节点域名的 A 记录指向 VPS 公网 IPv4。仅在 VPS 的 IPv6 入站已可用时添加 AAAA。关闭该域名的家宽 DDNS。
2. 准备独立节点的订阅域名和上游。Hysteria 2/TUIC 使用统一域名的有效证书，家庭无入站时用 DNS-01 签发。在登记 VPS 入口后验证域名并启动节点。
3. 在 VPS 上准备与 **VPS 控制地址**匹配的 TLS 证书及私钥。控制地址可以使用独立域名。将签发该证书的 CA 证书安全交给家庭端。使用 `openssl rand -hex 32` 生成独享的隧道令牌，将令牌保存到权限为 `0600` 的 VPS 文件。
4. 按以下模板配置并验证 `frps`。示例允许 Reality 的 TCP 8443 和原生 Hysteria 2 的 UDP 8442，请替换成实际使用的 VPS 公网端口。VPS 公网端口默认与本机监听端口相同，可在管理页分别设置。

```toml
bindAddr = "0.0.0.0"
bindPort = 7000
allowPorts = [{ single = 8443 }, { single = 8442 }]
auth.method = "token"
auth.additionalScopes = ["HeartBeats", "NewWorkConns"]
auth.tokenSource.type = "file"
auth.tokenSource.file.path = "/etc/frp/token"
transport.tls.force = true
transport.tls.certFile = "/etc/frp/fullchain.pem"
transport.tls.keyFile = "/etc/frp/privkey.pem"
```

```sh
frps verify -c /etc/frp/frps.toml
frps -c /etc/frp/frps.toml
```

5. 在 VPS 防火墙和安全组开放对应的 TCP 7000、TCP 8443、UDP 8442。家庭端只需要连接 VPS 的 TCP 控制端口，无需家宽端口转发。验证后可在 VPS 使用仓库的 `deploy/systemd/hopworld-frps.service` 随系统启动。将二进制放到 `/usr/local/bin/frps`，创建专用系统账号和组 `hopworld-frp`，确保它们能读取 `/etc/frp` 下的配置、证书、私钥和令牌文件，再安装单元并执行 `sudo systemctl daemon-reload` 和 `sudo systemctl enable --now hopworld-frps`。
6. 在「公网接入 → VPS 管理」填写统一节点域名、VPS 公网 IP 或独立控制域名、控制端口、令牌和 PEM 格式 CA 证书，先保存 VPS 配置。回到「内核管理」验证域名绑定并启动仅监听本机的独立节点，再回 VPS 管理勾选该节点和设置公网端口。Shadowsocks 的 TCP 和 UDP 共用一个公网端口。保存后在「隧道配置」查看注册状态。修改公网端口后，客户端需要刷新订阅或重新导入节点 URI。
7. 从蜂窝或异地网络导入真实节点，分别验证 TCP 入站、QUIC 握手和 UDP 业务。停止两端任一隧道进程时，从外网确认入口停止响应，恢复后复测。域名应持续解析到 VPS。

设置在 Router 重启后恢复，手动停止状态也会保存。已映射内核重新配置时，FRP 会短暂重连。若节点更改域名或监听端口，需重新保存 VPS 映射。端口注册表示 frps 已接受绑定，公网防火墙、DNS 和代理握手仍需从异地验证。令牌随 SQLite 快照保存，备份文件需要按凭证保管。可运行 `.venv/bin/python -m tests.e2e_relay` 做真实进程回环联调，所需二进制环境变量见脚本开头。

本地回归通过 171 项测试。Chrome 验证了已绑定域名选择、PEM 上传、节点文件下载和窄屏下的上游改名及扫码导出。二维码解码结果与 Xray 发布节点的完整 URI 一致。回环联调验证了六个独立内核的 TCP/UDP 业务、FRP 断线重连、证书替换后的 Hysteria 2 以及固定上游故障时的阻断。证书续签测试使用临时证书与模拟 Certbot。通过加密备份还原到新目录后，原管理员可登录，原 Hysteria 2 URI 通过证书校验并转发 TCP 与 UDP。

正式发布仍依照交付包的验收矩阵。VPS 已接入管理页，本机回环可验证端口冲突、断链、重连和真实 TCP/UDP 数据。多域名证书同时生效、自动升级失败回滚和正式发布签名仍有开发工作。家庭 CGNAT、VPS 安全组、真实 DNS-01 续签、异地客户端和干净 x86_64 Linux 主机仍需验收。
