# V1 网络安全与验收

## 可用范围

本阶段在「系统设置 → 网络安全」提供独立 sing-box 发布实例的加密 DNS 策略。可添加 DoH 或 DoT 解析器、保存草稿、校验内核配置、异步应用或回滚，并对当前运行版本发起诊断。诊断记录 A/AAAA 响应、观察到的 IPv4/IPv6 地址、检测时间和版本。实际公网出口归属仍需与独立网络证据比对。

| 能力 | 当前状态 |
| --- | --- |
| 独立 sing-box 的固定 SOCKS5 出口 | 支持兼容模式加密 DNS，语法锁定到 sing-box 1.14.4 |
| Xray-core、mihomo、原生 Hysteria 2 | 保留各自固定上游能力。统一加密 DNS 和严格出口待适配 |
| shadowsocks-rust、原生 TUIC | 当前发布适配器使用直连。严格模式不可用 |
| Linux 原生隔离出口 | 支持专用发布命名空间的隔离试验，以及命令行独立配置的 LAN 网关。管理端严格发布尚未开放 |
| 多 WAN、智能分流、VPS 隧道故障与回程 | 安全策略和专用验收待完成 |
| Docker、OpenWrt、macOS、Windows/WSL2、iOS | macOS 可生成和应用兼容模式配置。各平台真实防泄漏效果均待分别验证 |
| LAN 网关 DNS 接管 | Linux 独立网关已在隔离 LAN 验证双栈接管和故障阻断。实际 LAN 和公网待测 |
| HopWorld 客户端 TUN、浏览器 DNS / DoH / WebRTC ICE | 待客户端实现或实测 |

与现有运行方式分开，兼容策略只覆盖所选发布实例收到的代理流量。经节点传入的 TCP/UDP 53 由 sing-box 接管，853 由此模式阻断。普通域名目的地址经同一个加密解析器解析，业务出站只有指定 SOCKS5。未知的 HTTPS 443 内加密 DNS 无法靠端口判定。ACME、订阅更新、DDNS 和 VPS 隧道由独立控制面执行。业务进程无需 DNS 引导授权，控制面细粒度例外与审计待实现。

## 配置与回滚

1. 在「节点管理」导入一个地址为固定 IP 的 SOCKS5 上游，并在「内核管理」启动使用该上游的独立 sing-box 发布实例。UDP 中继须实测。
2. 在「系统设置 → 网络安全」选择发布实例并新增解析器。填写实际固定 IPv4/IPv6 地址、服务端口及证书域名。DoH 另需 HTTPS 路径，例如 `/dns-query`。
3. 保存策略，校验配置，再应用。应用过程中所选实例会重启。后台显示已应用版本及待验证状态。
4. 用「诊断发布入口」经该节点查询 `example.com` 的 A 和 AAAA，并访问 ipify 的 IPv4、IPv6 观察点。诊断结果只对应此入口和运行版本。
5. 用「回滚」恢复上一应用版本。回滚首个版本会解除兼容 DNS 策略并恢复该实例原有配置。绑定生效期间，如需更换上游或内核，先回滚解除绑定。

以下 API 请求为格式示例，地址与域名需要替换为实际解析器。接口要求管理员会话或 Basic 认证，写操作还要求同源 Origin。

```json
{
  "name": "业务解析器",
  "protocol": "doh",
  "address": "192.0.2.30",
  "port": 443,
  "server_name": "resolver.example.test",
  "path": "/dns-query"
}
```

解析器、版本、作业和审计由 SQLite 新表保存。草稿版本和活动版本独立。当前没有来自生产网络的验证版本。诊断记录状态、计数和观察地址，业务查询域名与代理密钥不写入诊断记录。中断作业在重启后标记为 `INCONCLUSIVE`。

## Linux 隔离试验

实验需要 Linux 原生环境、iproute2、nftables、tcpdump、OpenSSL 和对应架构的 sing-box。2026-11-20 在隔离 Ubuntu 24.04 ARM64 VM 使用官方 sing-box 1.14.4 发行包验证。ARM64 归档 SHA-256 为 `436441f76ee2f7fe21b5b2d426d3cb261a480455a704865789ad533e4273ec26`。[sing-box 1.14.4 发行页](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4)

在测试机仓库根目录复测。测试会创建临时 veth 与独立命名空间，进程退出时清理，并可将仅包含实验流量的观察点抓包保存到指定路径。

```sh
sudo env PYTHONPATH=. \
  HOPWORLD_SINGBOX=/absolute/path/to/sing-box \
  HOPWORLD_SECURITY_CAPTURE=/tmp/hopworld-egress-lab.pcap \
  python3 tests/e2e_network_security.py
```

如需单独审查规则，可用 `plan` 输出规则。已有专用命名空间时，`check` 会预检接口、路由和规则语法，`apply` 会先阻断再原子安装白名单。应用失败时保持阻断，`status` 可检查规则与计数，`block` 可立即撤销允许规则。

```sh
python3 -m router.egress_guard plan \
  --namespace hwr-sec-lab --interface wan0 \
  --upstream 192.0.2.20 --upstream-port 1080 \
  --listen-port 8444 --listen-port 8445
```

该隔离试验将出站 UDP 通过 sing-box SOCKS5 UDP over TCP v2 转发，只允许指定接口上的固定 SOCKS5 TCP 端点。入站 QUIC 的回包按 conntrack 方向和监听端口放行。测试进程以无特权用户运行。自定义命名空间须专用于这套业务，避免混用其他防火墙或服务。删除外部命名空间前先停止其中的发布进程。

## Linux 独立 LAN 网关

通过网关的 LAN IPv4/IPv6 流量由策略路由送入 TUN。普通 TCP/UDP 53 改由配置的 DoH 或 DoT 解析器处理。TCP、UDP、加密 DNS 都经固定的 SOCKS5 出口，UDP 需要上游支持 UDP over TCP v2。客户端以网关的 LAN 地址作为默认路由，并使用一个可路由的 DNS 目的地址。以网关监听地址为目的地的本机 DNS 请求会失败，因为此网关使用转发路径接管 DNS。

TUN 运行在独立用户及网络命名空间内，使用映射到主机专用用户的 `CAP_NET_ADMIN` 管理自己的虚拟网卡。由主机管理的外侧命名空间负责防火墙和 NAT，只放行已固定的转接源 IP、SOCKS5 目标 IP、端口和回程。两层规则默认阻断，网关进程退出后保持关闭。请将 SSH 和 Router Web 后台留在现有管理网络。设备上的蜂窝、备用网关、其他 VPN 及浏览器候选地址需分别验收。[sing-box TUN 文档](https://sing-box.sagernet.org/configuration/inbound/tun/)

### 新服务器部署预检

普通 Router 和 sing-box 兼容加密 DNS 可按各自运行条件部署。需要严格 LAN 网关时，优先选择运行原生 Linux 的完整虚拟机或物理机。已在 Ubuntu 24.04 ARM64 验证。Debian 12 等其他镜像、VPS 与容器环境均以目标机实际预检为准。容器宿主机可以限制 TUN、用户命名空间或 netfilter，添加软件包只能解决相应命令缺失的问题。[Linux 内核用户命名空间说明](https://docs.kernel.org/admin-guide/sysctl/user.html)

在源码目录运行下列命令。安装 Debian 包时，工作目录为 `/usr/lib/hopworld-router`。Ubuntu/Debian 若缺少系统工具，可按预检结果安装对应可选包。

```sh
sudo apt install iproute2 nftables procps util-linux
sudo python3 -m router.linux_gateway preflight
```

预检输出 JSON，并在一次性命名空间中检查用户与网络命名空间、受限网关身份、TUN 和 nftables 规则。它也会检查双栈策略路由的 JSON 输出和 `setpriv` 参数。预检不会安装主机防火墙规则或变更现有路由。[Ubuntu iproute2 参数](https://manpages.ubuntu.com/manpages/noble/man8/ip.8.html) · [Debian setpriv 参数](https://manpages.debian.org/bookworm/util-linux/setpriv.1.en.html)

| 状态 | 退出码 | 部署含义 |
| --- | --- | --- |
| `READY_FOR_TOPOLOGY` | 0 | 主机能力通过，可配置专用网络拓扑，再执行 `check` 并跑实际 DNS、出口和故障阻断测试 |
| `BLOCKED` | 1 | 从 `checks` 查看缺项。缺工具时安装对应包，内核或 VPS 权限受限时更换主机或镜像。普通 Router 可独立部署 |
| `NEEDS_ROOT` | 2 | 已检查静态依赖，需以 root 验证内核能力 |

CentOS 7.6 服务器实测可运行兼容 DNS。该机缺少 nftables，用户命名空间无法启用，`iproute2` 缺少 JSON 输出，`setpriv` 缺少退出联动参数，严格网关部署应视为阻塞。公网 IPv6 单独验收，查询到 AAAA 记录只能证明 DNS 返回了 IPv6 地址。

### 配置拓扑与运行

准备两个专用命名空间及一对转接 veth。工作命名空间包含 `lan0`、`uplink0`，外侧命名空间包含 `transit0`、`wan0`。两端需要各自的 IPv4/IPv6 转发，外侧还需要连接上游的路由。内置 TUN 地址为 `198.18.254.1/30` 和 `fd94:bc9e:26ea::1/126`，策略路由使用表 `23941` 和优先级 `10141`。

以下为 `gateway.json` 格式示例。请替换为实际网络、解析器及专用 UID/GID。上游如需认证，可在 `upstream` 同时填入 `username`、`password`，并将文件设为仅管理员可读。

```json
{
  "worker": "hwr-sec-gateway",
  "edge": "hwr-sec-edge",
  "lan": "lan0",
  "worker_transit": "uplink0",
  "edge_transit": "transit0",
  "uplink": "wan0",
  "lan_networks": ["10.80.1.0/24", "fd62:80:1::/64"],
  "transit_ip": "192.0.2.2",
  "worker_uid": 61077,
  "worker_gid": 61077,
  "upstream": {"address": "198.51.100.20", "port": 1080},
  "resolver": {
    "name": "网关解析器",
    "protocol": "doh",
    "address": "192.0.2.30",
    "port": 443,
    "server_name": "resolver.example.test",
    "path": "/dns-query"
  }
}
```

先运行 `plan` 查看规则，再用 `create-worker` 创建工作命名空间。用 `ip netns add hwr-sec-edge` 创建外侧命名空间，由管理员按上述拓扑布置网卡和路由。完成后运行 `check`。预检通过后，`run` 会先阻断外侧，再启动 TUN、接管 LAN 路由，最后开放固定上游。

```sh
python3 -m router.linux_gateway plan --config gateway.json
sudo python3 -m router.linux_gateway create-worker --config gateway.json
sudo python3 -m router.linux_gateway check --config gateway.json --sing-box /absolute/path/to/sing-box
sudo python3 -m router.linux_gateway run --config gateway.json --sing-box /absolute/path/to/sing-box
```

正常停止用 Ctrl-C 或向运行进程发送 SIGTERM。用 `sudo python3 -m router.egress_guard status --namespace hwr-sec-edge` 查看外侧规则和计数。停止后应只剩默认阻断规则。随后可以撤销客户端默认路由，再删除专用命名空间。若监督进程被强制终止，TUN 会随之退出。此时用 `sudo python3 -m router.egress_guard block --namespace hwr-sec-edge` 显式关闭外侧，再重建工作命名空间以清除残余路由。

复测脚本在 Linux 内核实际创建独立 LAN、网关、外侧防火墙和 WAN 观察点。分别使用 `HOPWORLD_TEST_GATEWAY_UNDERLAY=4` 和 `=6` 复测两种 SOCKS5 底层路径。双栈环境中，STUN 观察点使用非固定服务端口验证请求来自选定上游。[RFC 8489](https://www.rfc-editor.org/rfc/rfc8489)

```sh
sudo env PYTHONPATH=. HOPWORLD_TEST_GATEWAY_UNDERLAY=4 \
  HOPWORLD_SINGBOX=/absolute/path/to/sing-box \
  HOPWORLD_SECURITY_CAPTURE=/tmp/hopworld-gateway-v4.pcap \
  python3 tests/e2e_linux_gateway.py
```

## SEC 验收进度

| 用例 | 本次证据 | 现场状态 |
| --- | --- | --- |
| SEC-01 | 同一隔离出口的 DoH A/AAAA、入站 TCP/UDP 53 接管、兼容模式的 DoT A/AAAA | 生产 WAN 与独立解析器待测 |
| SEC-02、03 | 隔离 LAN 的 IPv4/IPv6 普通 DNS 均经 TUN 接管，覆盖 TCP 和 UDP | 实际 LAN 与受管浏览器 DoH 待测 |
| SEC-04、05 | IPv4 与 IPv6 SOCKS5 底层分别验证双栈业务 TCP/UDP 和 STUN，外侧 veth 无非授权 TCP/UDP 包 | 真实双栈 WAN 与浏览器 WebRTC ICE 待测 |
| SEC-06 | SOCKS5 停机后新 TCP、UDP、DNS 请求失败。网关内侧规则被移除及 TUN 崩溃时，外侧保持阻断。错误解析器证书名称无法完成查询 | 多上游切换和独立网络超时待测 |
| SEC-07 | — | 真实 VPS 隧道断线待测 |
| SEC-08 | sing-box 发布 Hysteria 2、TUIC 经受控上游运行 | 其余内核及组合待测 |
| SEC-09、10 | nftables 仅作用于测试命名空间 | 多 WAN、地址变更、真实 ACME/管理通道联合验收待测 |
| SEC-11 | 无效接口触发失败后保持全阻断，TUN 崩溃后可重新通过预检 | 生产条件下失败与回滚待测 |
| SEC-12 | 兼容配置可经 Router 发布恢复流程重新应用，已试验回滚 | Linux 重启及生产编排的先阻断后恢复待测 |
| SEC-13、14 | 后台只报告发布入口观测结果，展示客户端侧及加密 DNS 的覆盖限制 | 客户端与第三方加密 DNS 实测待完成 |

当前提供兼容 DNS 配置和 Linux 独立 LAN 网关。严格生产发布仍待验收，生产实例的 `verified_revision` 保持为空。
