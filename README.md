# HopWorld Router

HopWorld Router 是计划独立运行的代理服务项目，源自 [HopWorld](https://github.com/ZaoHub/HopWorld) 的软路由功能。

**当前状态：项目规划阶段，尚不可部署或使用。**

## 计划中的第一版

- Linux x86_64 和 ARM64；提供 Docker 部署方式。
- HTTP 和 SOCKS5 代理入口。
- 订阅管理、节点测试、自动优选与延迟换线。
- 浏览器管理界面，包含认证、运行状态和日志。
- 配置持久化、服务启动与异常恢复。

第一版的接入方式是客户端主动配置代理。透明网关、OpenWrt 和 Windows 服务需另行设计与验证。

## 部署目标

以下均为规划，尚未实现或验证。各平台的支持范围以实际发布和测试结果为准。

| 部署目标 | 计划方式 | 主要调整 |
| --- | --- | --- |
| Linux 云服务器、VPS | 独立程序 + systemd | 后台运行、开机启动、进程守护、安全的远程访问 |
| Linux 小主机、虚拟机 | 同一套 Linux 程序 | 与 VPS 基本相同；如需当网关，还要增加网络接管功能 |
| Docker、支持容器的 NAS | x86_64 / ARM64 镜像 | 持久化配置、端口映射、日志和健康检查；还需验证设备架构与系统兼容性 |
| OpenWrt 路由器 | 后续制作适配包 | 考虑 CPU 架构、存储与内存，以及 OpenWrt 的服务和防火墙管理 |
| macOS | 保留现有应用，或后续运行独立服务 | 如需退出界面后仍运行，需要独立后台服务 |
| Windows 服务器 | 后续单独适配 | Windows 服务、进程管理、路径和凭据存储 |

优先实现 Linux 和 Docker 的代理服务；旁路由或网关还需要单独设计透明转发、DNS、IPv6 和故障恢复，并在目标设备上验证。

## 安全原则

管理界面和代理入口需要访问控制；部署时不得默认向公网开放无认证代理。订阅地址、节点凭据、令牌及服务器私钥不能提交到仓库。实际部署前仍需验证安全配置和网络隔离。

## 项目关系

本项目独立于 HopWorld macOS 应用开发和发布。现有实现可作为设计和移植参考；支持范围以本项目实际实现和测试结果为准。
